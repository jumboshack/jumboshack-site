Setup guide

Stream your weather station into Jumboshack

Push your backyard weather station — temperature, wind, rain, pressure, humidity — into your Jumboshack dashboard. It rides the same Custom endpoint anything can post to, so there's no special weather hardware or new software to build: a tiny relay reads your station and forwards the numbers. About 20 minutes.

⏱️ ~20 minutes 🧰 A WiFi weather station + any always-on computer 🛠️ Beginner-friendly — a short copy-paste script
How it works: weather stations report to a cloud API (Ambient Weather, Ecowitt) or a local gateway. A small relay reads those numbers every few minutes and POSTs them to your Jumboshack Custom device — where they auto-render as cards + trend charts. Nothing is written back to your station; it's read-only.
The four steps
  1. Get a WiFi weather station
  2. Create a Jumboshack Custom device
  3. Run the relay
  4. Verify & label

How it fits together

  Weather station ──(WiFi)──► vendor cloud / local gateway
                                      │
                        weather relay  (reads the API, POSTs over HTTPS)
                                      │

1

Get a WiFi weather station

Any station with a cloud API or a local network gateway works. The common, well-documented ones:

StationHow you read itPrice
Ambient Weather (WS-2902 etc.) Simple REST API (application key + API key). Temp, wind, rain, pressure, humidity, UV, solar. on Amazon
Ecowitt (GW1100 / GW2000 gateways) Local network API on the gateway and an Ecowitt cloud API — no cloud dependency if you use local. on Amazon
WeatherFlow Tempest REST + UDP local broadcast. Sonic wind, haptic rain, lightning. on Amazon

2

Create a Jumboshack Custom device

In your Account, add a Location if needed, then add a Device and set its module to custom. Copy the one-time token (jsk_…). That token ties your weather readings to your account, and they'll appear on the Custom tab (which you can rename to “Weather” — double-click the tab, or Account → Navigation tabs).

3

Run the relay

A small script reads your station and POSTs a metrics map to /api/ingest/custom every few minutes. Here it is for Ambient Weather (pure Python, no dependencies) — schedule it from cron on any always-on box:

# weather-relay.py — Ambient Weather → Jumboshack Custom
import json, urllib.request
from datetime import datetime, timezone

AMBIENT_APP_KEY = "your_application_key"   # dashboard.ambientweather.net → API keys
AMBIENT_API_KEY = "your_api_key"
JUMBO_TOKEN     = "jsk_your_custom_device_token"

url = f"https://api.ambientweather.net/v1/devices?applicationKey={AMBIENT_APP_KEY}&apiKey={AMBIENT_API_KEY}"
d = json.load(urllib.request.urlopen(url, timeout=15))[0]["lastData"]

# map the station's fields to clean metric names (see naming tips below)
metrics = {}
for src, dst in (("tempf","temp_f"), ("humidity","humidity_pct"), ("windspeedmph","wind_mph"),
                 ("windgustmph","gust_mph"), ("hourlyrainin","rain_in"), ("baromrelin","pressure_inhg"),
                 ("uv","uv"), ("solarradiation","solar_wm2")):
    if d.get(src) is not None:
        metrics[dst] = float(d[src])

body = json.dumps({"metadata": {"time": datetime.now(timezone.utc).isoformat(),
                                "software_version": "weather-relay/1.0"},
                   "metrics": metrics}).encode()
req = urllib.request.Request("https://ingest.jumboshack.com/api/ingest/custom", data=body,
        method="POST", headers={"Authorization": f"Bearer {JUMBO_TOKEN}",
                                "Content-Type": "application/json"})
print(urllib.request.urlopen(req, timeout=20).read().decode())

Test it once, then schedule every 5 minutes:

# dry run first — validates + echoes what was understood, stores nothing
# (add ?validate=1 to the URL in the script, run once, then remove it)

crontab -e
*/5 * * * * /usr/bin/python3 /home/pi/weather-relay.py > /home/pi/weather.log 2>&1
Other stations, same idea. Ecowitt: read the local gateway API (http://<gateway-ip>/get_livedata_info) or the Ecowitt cloud API and map the fields the same way. Tempest: use the WeatherFlow REST API. Home Assistant users: if your station is already in HA, a REST-command automation can POST the same metrics JSON to /api/ingest/custom on a timer — no separate script.
4

Verify & label

Within a few minutes, open your Custom tab — each metric shows as a card with a hover trend (daily high/low/avg). Rename the tab to “Weather” (double-click it) if you like.

Metric-naming tips (so it auto-formats)

  • temp_f → shows °F; humidity_pct → % — these format automatically.
  • wind_mph, gust_mph, rain_in, pressure_inhg, uv, solar_wm2 show as plain numbers — set a unit label (mph, in, inHg, W/m²) with the ✎ on each card, once.
  • Only numeric values are stored; send whatever your station reports. Full format: the API guide (“Custom — any numbers you want”).

Troubleshooting

  • 401? Wrong token, or the device isn't set to the custom module — re-copy from Account.
  • Ambient API empty? Give it a minute after generating keys; make sure the station is online in the Ambient app.
  • Nothing on the Custom tab? Run the script by hand and check the response is {"ok":true,…}; confirm the station is reporting.
