Setup guide

Stream your air quality into Jumboshack

Add a WiFi Airthings monitor and watch radon, CO₂, VOCs, particulates and humidity land on your Jumboshack dashboard — right alongside your heat pump. There's nothing to build: Airthings does the sensing, and one tiny sender relays your readings over your account's API. About 20 minutes, most of it clicking through the Airthings dashboard.

⏱️ ~20 minutes (plus buying the monitor) 🧰 A WiFi Airthings + any always-on computer 🛠️ Beginner-friendly — no wiring, no soldering
It must be a WiFi Airthings. Jumboshack reads your data through the Airthings cloud API, so the monitor has to report to your Airthings account over WiFi — a View Plus, View Radon, View Pollution, or a Wave-series device paired with an Airthings Hub. Bluetooth-only units (like the Corentium Home) never reach the cloud and can't be used here.
The four steps
  1. Get a compatible monitor
  2. Turn on Airthings API access
  3. Create a Jumboshack device token
  4. Run the sender & verify

How it fits together

Your Airthings monitor already uploads to Airthings' cloud. A small pure-Python sender — light enough to run on a $15 Pi or as a container on your NAS — signs into that cloud with your API key, grabs each room's latest reading every few minutes, and POSTs it to Jumboshack over HTTPS:

  Airthings monitor ──(WiFi)──► Airthings cloud
                                      │
                       airthings-sender  (reads the API, POSTs over HTTPS)
                                      │
                          ingest.jumboshack.com → your dashboard

It's read-only — it only ever reads your Airthings data; it changes nothing on your account or device. Readings are keyed by their own timestamp, so a missed cycle simply backfills on the next one, and a network blip never costs you data.

2

Turn on Airthings API access

Jumboshack reads your data through Airthings' own API, so you'll create an API client and copy three values. This lives in the Airthings web dashboard, not the phone app.

  1. Sign in at dashboard.airthings.com.
  2. Go to Integrations → API and create an API client. Choose the client-credentials type and grant the scope read:device:current_values.
  3. Copy your Client ID and Client Secret (the secret is shown once — save it now).
  4. Note your Account ID (shown in the API / account area).
Read-only by design. That single scope only lets the sender read current values — it can't change settings or control your device. Your keys stay on the machine you run the sender on; they never come to Jumboshack.
3

Create a Jumboshack device token

In your Jumboshack Account, add a Location if you don't have one, then add a Device and set its module to air quality. You'll get a one-time token that looks like jsk_… — copy it now; it's shown only once. That token ties your Airthings readings to your account (one device represents your whole Airthings account; each monitor shows up as its own room).

4

Run the sender & verify

The sender is open-source, pure Python, with no dependencies — run it with Docker on any always-on box (a spare Raspberry Pi, a mini-PC, or a container on your NAS).

# grab the sender
git clone https://github.com/jumboshack/jumboshack-sender.git
cd jumboshack-sender/airthings-sender

# fill in your five values
cp .env.example .env
nano .env

Your .env holds the three Airthings values plus your Jumboshack device token — it's gitignored, so nothing leaves your machine:

# .env
AIRTHINGS_CLIENT_ID=your_client_id
AIRTHINGS_CLIENT_SECRET=your_client_secret
AIRTHINGS_ACCOUNT_ID=your_account_id
INGEST_TOKEN=jsk_your_device_token_here

Dry-run first

Do a validation run — it fetches from Airthings and checks the payload against the server but stores nothing, so you can confirm the plumbing before going live:

docker build -t airthings-sender .
docker run --rm --env-file .env -e VALIDATE=1 airthings-sender

A line like dry run OK ✓ with a room count means you're good.

Go live

Start it in the background — it streams every five minutes and restarts with your machine:

docker compose up -d
# (or)  docker run -d --restart unless-stopped --name airthings-sender --env-file .env airthings-sender

Within a few minutes, open Air Quality ▸ Now — each monitor appears as a room with its radon, CO₂, VOC, PM and humidity, and Trends and History fill in from there.

Troubleshooting

  • Dry run says 401/403? The Jumboshack token is wrong or the device isn't set to the air quality module — re-copy the token from Account (add a fresh device if it's lost, since it's shown once).
  • Airthings login fails? Double-check the Client ID/Secret and that the API client has the read:device:current_values scope. Regenerate the secret if you didn't save it.
  • “no readings from Airthings”? Make sure the monitor is online in the Airthings app and has taken readings. A brand-new device can take a little while for its first values.
  • Rooms grouped oddly by floor? Set FLOOR_MAP_JSON in .env to label and order them, e.g. {"2960123636":["Main Floor",2]}.
  • Bluetooth-only device? A Corentium Home (or any non-WiFi unit) can't reach the cloud API and won't work — you'd need a WiFi View, or a Wave paired with a Hub.
